### FR별 세부 — 명세 요구사항 대조

**FR-1 단계형 입력** — 완료

- 출발지→도착지→날짜→도착 마감 시각→인원 5단계, 진행 표시 "5단계 중 N번째", [이전] 상시 노출
- 자동완성(역/터미널·지역 구분 표시), 현재 위치 기반 추천(자동 확정 안 함, 권한 거부해도 키보드 진행)
- [오늘]·[내일] 버튼에 실제 날짜·요일 표시, 달력 지난 날짜 비활성
- 시·분 선택기 5분 단위, "오후 2시까지 도착" 문구 표시
- 노약자/성인/학생 스테퍼, 총인원 1명 이상일 때만 [다음] 활성
- 비활성 버튼 옆 안내 문구("출발지를 선택하면 다음으로 갈 수 있어요") — 서버가 문구 생성
- ※ `backend/static/index.html`은 참조 구현. 프론트 본 구현(React)은 이 화면과 API를 그대로 따라가면 됨

**FR-2 입력 검증** — 완료 (전부 서버가 판단하므로 프론트 실수로 뚫리지 않음)

- 출발지=도착지 차단, 지난 날짜 차단, 당일 지난 시각 차단, 총인원 0명 차단 + 안내 문구
- 추가 방어(점검에서 보강): 잘못된 날짜 형식, 음수 인원, 범위 밖 시각 모두 거부

**FR-3 이동·복귀** — 완료

- [이전] 값 유지, 재진입 시 [이어서 하기]/[처음부터 다시], 로그인 없이 세션 저장
- [데모 초기화]: 입력값·시뮬 예약·서버 알림 일괄 삭제

**FR-4 확인 요약** — 완료

- 명세 예시 형식 그대로 요약 문장 생성("대전 → 부산", "7월 15일 수요일", "총 2명"…)
- 행 탭 → 해당 필드만 수정 → 요약 복귀, 다른 값 유지

**FR-5 통합 검색** — 완료

- KTX·ITX-새마을·무궁화호·SRT·고속·시외 통합 조회, 유형별 할인 적용 총요금
- 학생 할인 규칙 미확인 수단은 성인 운임 + "학생 할인 미적용" 표시 (명세 그대로)
- **열차는 실데이터 동작 확인**: 서울→부산 83편 실시간, 실제 요금 반영
- 개별 수단 장애 시 성공분 유지 + "일부 교통편은 확인하지 못했어요" / [다시 확인] / [확인된 결과만 보기]
- 남음: 고속·시외버스 실조회는 `TAGO_API_KEY` 필요 (어댑터는 완성, 키만 넣으면 켜짐)

**FR-6 좌석 상태** — 완료

- 좌석 상태 5종(LIVE_/SIMULATED_ 있음·매진, UNKNOWN) 명세 정의 그대로
- 코레일(KTX·ITX·무궁화호) **실시간 조회 동작 확인** — 매진 편 자동 제외 (실측 25편 제외)
- UNKNOWN은 매진 처리 안 함 → "좌석 정보를 확인하지 못했어요" + 3버튼, 별도 영역 표시
- 버스 좌석은 시뮬레이션 (명세 지정)
- 남음: SRT 실조회는 `SRT_ID/PW` 필요 (SRT는 조회에도 로그인 필요)

**FR-7 여정 재조합** — 완료

- 1순위 매진 시 환승≤1·대기≥20분·소요≤직결최속 1.5배 조건으로 대체 경로 최대 3개
- 추천 근거 키·제외 사유 출력, UNKNOWN 비간주, 마감 초과 제외 — 명세 규칙 전부 반영
- 남음: 상세 탐색·점수화 알고리즘 문서를 명세 본 항목에 추가 (§6 추후 확정 사항)

**FR-8 경로 제시** — 완료

- 카드 최대 3개(빠름·저렴·직통 대표편 우선), 추천 근거·유형별 요금·출처 3종 표시
- LLM 한 문장 설명 + **사후 검증**: 숫자를 지어내거나 근거 없는 "가장 저렴" 주장은 폐기 후
  정형 문구 대체 (실제 위반 2회 발견해서 만든 장치 — 심사 질문 대비 포인트)
- LLM 실패 시 정형 문구 폴백 → 인터넷 없어도 흐름 안 끊김

**FR-9 선점·결제 시뮬레이션** — 완료

- SIM_* 상태 7종, [상관없음/창가/통로] 옵션, 인접 좌석 우선, "(시뮬레이션 좌석)" 표시
- "오후 3시 42분까지 · 12분 남음" 절대시각+남은시간, 15분 만료(SIM_EXPIRED)
- 결제 화면 상단 고정 문구, 카드정보 입력·저장 없음, DEMO_COMPLETED만 생성(PAID 없음)
- 경합 실패 시연: "방금 자리가 나간 상황을 시연하고 있어요" + [다른 길 찾기]→재조합

**FR-10 이메일 알림** — 완료(설정 대기)

- 전날 오후 6시 + 출발 2시간 전(KST), 임박 시 즉시 1회 — 알림 큐 등록 동작 확인
- 제목·본문 "[경진대회 시연용 알림]" 명시, [알림 시연] 즉시 발송 버튼
- 마지막 알림 전송 후 서버 데이터 삭제 (점검에서 누락 발견 → 구현 완료)
- 남음: 실발송용 `DEMO_EMAIL_TO`/`SMTP_*` 값 (미설정이면 "전송 실패"를 정직하게 표시하고 데모는 계속)

**FR-11 예약 확인** — 완료

- 첫 화면 최상단 진행중 카드("예약 시뮬레이션이 진행 중이에요 — …분 남음"), 시뮬레이션 배지 상시
- DEMO-XXXXXX 데모 번호만 생성 (실제 사업자 예약번호 형식 금지)

| 2 | 카드에 운행정보·좌석·예약 각각 출처 표시 | 완료 — 서버가 표시 문구까지 생성 |

| 5 | [시뮬레이션으로 보기] 선택 시에만 대체 + 고지 | 완료 — 카드에 전환 문구 덧붙임 |
| 6 | 예약·결제 함수 백엔드에서도 비활성화 | 완료 — 예약 진입점 없음 + 호출 시 예외 차단 |
| 7 | 데모 초기화 일괄 삭제 | 완료 |

## 4. 남은 일 정리

**키·계정만 넣으면 되는 것** (코드 완료, `backend/.env`에 채우면 켜짐):

1. `TAGO_API_KEY` — data.go.kr에서 국토부(TAGO) 열차·고속버스·시외버스 3종 활용신청 → 버스 실조회 켜짐
2. `SRT_ID` / `SRT_PW` — SRT 회원 계정 → SRT 실조회 켜짐
3. `DEMO_EMAIL_TO` / `SMTP_*` — 시연용 이메일 실발송

**팀에서 정해야 하는 것**:

4. 학생 할인 규칙 확정 (§6) — 지금은 명세 규칙대로 성인 운임 + "학생 할인 미적용" 표시라 미정이어도 안전
5. 노약자·학생 할인율 검증 — 현재 값은 시연용 근사치

**백엔드 후속 작업**:

6. FR-7 상세 탐색·점수화 알고리즘 문서화 (§6 — 명세 본 항목에 추가)
7. API.md·DB.md v3 갱신 — 그때까지 v3 계약은 `http://localhost:8000/docs`(OpenAPI)가 기준
8. ODsay 복합 경로 (선택 — 시연에 필수 아님)

## 5. 프론트 팀원 참고

- 실행: `backend/README.md` — 키 없이 `TOOL_MODE=mock`(기본)으로 전 흐름 동작
- 참조 UI: `http://localhost:8000/app` (5단계 화면 전부 구현돼 있어 그대로 따라가면 됨)
- 시연 단축: `/app?fill&go` (입력 자동 채움 + 바로 검색)
- 호출 순서: `places/search` → `input/validate`×5 → `input/{sid}` → `search` → `sim/hold` →
  `open-payment` → `complete` → `notify/{demoId}/demo`
- 검증 문구·추천 근거·출처 표시는 전부 서버가 만들어 주므로 프론트는 표시만 하면 됨
