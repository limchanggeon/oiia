0. 문서 목적 및 범위

본 문서는 2026 AI·SW 소프트웨어중심대학 경진대회 출품용 프로토타입과 향후 목표 서비스의 기능 범위를 함께 정의한다.
목표 서비스의 기능과 대회 시연에서 실제로 동작하는 기능을 구분하며, 시뮬레이션 데이터가 실제 조회·예약 결과로 오인되지 않도록 모든 관련 화면에 출처를 표시한다.

데이터 표시 기준
- 실제 API 조회: 외부 운행정보·요금 API가 반환한 응답과 조회 시각
- 실시간 좌석: 좌석 조회 어댑터가 해당 시점에 반환한 좌석 상태
- 시뮬레이션: 경진대회 시연을 위해 준비한 목업 데이터 또는 목업 처리
- 확인 불가: 외부 조회가 실패하여 좌석 상태를 판단할 수 없는 경우

승객 유형 정의
- 본 문서에서 "노약자"는 할인 계산 목적상 만 65세 이상 승객을 뜻한다.
- 학생 할인은 확인된 사업자 규칙이 있을 때만 적용하며, 확인된 규칙이 없으면 성인 운임을 적용하고 "학생 할인 미적용"을 표시한다.

1. 서비스 정의

[목표 서비스]
노령세대(50–70대)가 한 화면에 하나씩 묻는 큰 글씨 단계형 화면으로 여정을 입력하면, AI가 KTX·SRT·고속·시외버스를 통합 검색해 매진을 걸러내고 예매 가능한 경로 2–3개만 큰 글씨로 보여준 뒤, 좌석 선점(가능한 수단에 한함)까지 대신하고 결제만 사람이 하는 이동 비서.

[경진대회 시연 범위]
- KTX·코레일 일반열차·SRT·고속버스·시외버스의 운행정보와 요금: 실제 외부 API 응답 사용
- KTX·코레일 일반열차·SRT의 좌석 상태: korail2·SRTrain을 이용한 실시간 조회 결과 사용
- 고속버스·시외버스의 좌석 상태: 시뮬레이션 데이터 사용
- 모든 교통수단의 좌석 선점·예약: 시뮬레이션
- 모든 교통수단의 결제: 시뮬레이션
- 사용자 로그인: 구현하지 않음
- 이메일 알림: 서버에 미리 등록된 데모 이메일 주소로 전송
- 상용화 시 사용자 교통사 계정 연동 및 사용 조건을 충족한 공식·제휴 B2B 예약 API로 교체

화면 표시 예시
- 열차: "운행정보 실제 API 조회 · 좌석 실시간 · 예약 시뮬레이션"
- 고속·시외버스: "운행정보 실제 API 조회 · 좌석/예약 시뮬레이션"
- 결제 화면: "대회 시연용 결제 화면 · 실제 결제되지 않음"

2. 시스템 구성

[모바일 웹앱 (반응형)]
   ├─ 5단계 입력 UI (한 화면 한 필드 · 토스 본인인증과 유사한 단계형 UX)
   ├─ 시니어 UI 컴포넌트 (큰 글씨·큰 버튼·명확한 안내 문구)
   ├─ 실시간/시뮬레이션 상태 배지
   └─ 데모 세션 저장·초기화

[백엔드 서버]
   ├─ 검색 오케스트레이터
   │     ├─ TAGO 열차·고속버스·시외버스 어댑터 (운행정보·요금)
   │     └─ ODsay 어댑터 (도시간 복합 경로)
   ├─ 열차 좌석 조회 어댑터 (조회 전용)
   │     ├─ korail2 (KTX·코레일 일반열차 좌석 조회)
   │     └─ SRTrain (SRT 좌석 조회)
   ├─ 여정 정규화·재조합 엔진
   ├─ 시뮬레이션 엔진
   │     ├─ 고속·시외버스 좌석 상태
   │     ├─ 전 교통수단 좌석 선택·선점·예약
   │     ├─ 예약 경합·만료·취소
   │     └─ 결제 화면·결제 결과
   ├─ LLM (확정된 경로 데이터의 비교 설명문 생성)
   └─ 이메일 알림 서비스 (미리 등록된 데모 이메일 사용)

[향후 상용화 연동]
   ├─ 사용자별 코레일·SRT 계정 연동 또는 승인된 철도 B2B 예약 API
   ├─ 고속·시외버스 좌석 조회·예약이 가능한 공식·제휴 B2B API
   └─ 실제 결제 및 결제 완료 상태 연동

시연 안전 규칙
- korail2·SRTrain의 예약 함수는 호출하지 않는다. 백엔드에서도 예약 기능을 비활성화한다.
- 개발자 계정은 필요한 경우 열차 좌석 조회에만 사용하며 클라이언트 코드와 로그에 노출하지 않는다.
- 동일 조건의 열차 좌석 조회는 짧은 시간 동안 캐시하고 중복 호출을 합친다.
- 좌석 조회의 동시 호출 수와 재시도 횟수를 제한하며 반복·무한 재시도를 금지한다.
- 실시간 좌석 조회 실패 후 시뮬레이션으로 전환할 때는 사용자에게 전환 사실을 명시한다.
- 시뮬레이션 예약과 결제는 실제 사업자 시스템, 실제 좌석 재고, 실제 금전 거래에 영향을 주지 않는다.

3. 기능 명세

FR-1. 단계형 여정 입력 (한 화면 한 필드)

설명
- 챗봇·자유 발화 방식 대신 한 화면에 필드 1개만 크게 표시한다.
- 입력이 끝나면 [다음] 버튼으로 다음 필드로 이동한다.
- 총 5단계로 구성한다.

입력 순서
① 출발지 → ② 도착지 → ③ 날짜 → ④ 도착 마감 시각 → ⑤ 인원 구성

공통 화면 구성
- 상단: 큰 제목 질문(예: "어디에서 출발하세요?")
- 중앙: 입력 영역
- 하단: 전체 폭 [다음] 버튼
- [이전] 버튼 상시 노출
- 상단 진행 표시: "5단계 중 현재 위치"
- 필드가 확정되기 전에는 [다음] 버튼 비활성
- 비활성 버튼 주변에 해야 할 행동을 큰 글씨로 표시
  예: "출발지를 선택하면 다음으로 갈 수 있어요"

필드별 입력 방식

① 출발지
- 키보드로 장소·역·터미널 이름 입력
- 입력 중 자동완성 후보 표시
- 현재 위치 기반 추천을 큰 버튼으로 함께 표시
- 추천값은 자동 확정하지 않으며 사용자가 눌러야 확정
- 위치 권한을 거부하거나 위치를 확인할 수 없어도 키보드 입력으로 계속 진행 가능
- 같은 이름의 역·터미널이 있으면 지역명과 시설 유형을 함께 표시

② 도착지
- 키보드로 장소·역·터미널 이름 입력
- 입력 중 자동완성 후보와 자주 가는 곳 후보 표시
- 자동완성 결과를 눌러야 입력값 확정

③ 날짜
- [오늘], [내일] 빠른 선택 버튼
- 버튼에 실제 날짜와 요일을 함께 표시
  예: "오늘 · 7월 11일 토요일"
- 다른 날짜는 큰 글씨 달력에서 선택
- 지난 날짜는 선택 불가

④ 도착 마감 시각
- 출발 시각이 아닌 "몇 시까지 도착" 기준으로 통일
- 시·분 선택기를 사용하고 분은 5분 단위(00, 05, 10, …, 55)로 제공
- 선택 결과를 "오후 2시 35분까지 도착"처럼 정확한 시각으로 표시

⑤ 인원 구성
- 다음 세 유형을 각각 [－] [＋] 스테퍼로 입력
  · 노약자(만 65세 이상): 기본 0명
  · 성인: 기본 0명
  · 학생: 기본 0명
- 총인원은 세 유형의 합으로 자동 계산
- 총인원이 1명 이상일 때만 [다음] 활성화
- 학생 할인은 확인된 사업자 할인 규칙이 있을 때만 적용하고, 규칙이 없으면 성인 운임 적용

라벨 규칙
- 버튼 라벨은 짧은 명사형 또는 명령형 사용
- 도착 기준 문구로 통일
  예: [오전 10시까지] ○ / [아침 출발] ×


FR-2. 입력 기본값·검증

출력
{
  departure: {name, type, canonical_id},
  arrival: {name, type, canonical_id},
  date,
  arrival_time,
  passenger_counts: {
    senior,
    adult,
    student,
    total
  }
}

기본값
- 출발지: 현재 위치 기반 가장 가까운 역·터미널을 추천값으로 표시하되 자동 확정하지 않음
- 도착지: 기본값 없음
- 날짜: 기본값 없음
- 도착 마감 시각: 기본값 없음
- 인원: 노약자(만 65세 이상) 0명, 성인 0명, 학생 0명

검증 규칙
- 출발지·도착지는 자동완성 또는 추천 후보를 눌러 확정해야 함
- 출발지와 도착지가 같으면 [다음] 비활성 및 안내 문구 표시
- 지난 날짜는 선택 불가
- 당일 검색에서 이미 지난 도착 마감 시각은 선택 불가
- 총인원이 0명이면 [다음] 비활성 및 "한 명 이상 선택해 주세요" 표시
- 위치 권한 거부는 오류로 처리하지 않고 키보드 입력 경로 제공


FR-3. 단계 이동·중단 복귀

동작
1. [이전]으로 돌아가도 이미 입력한 값 유지
2. 중도 이탈 후 재진입 시 "이어서 입력하시겠어요?" 표시
   - [이어서 하기]
   - [처음부터 다시]
3. 뒤로 가기·수정으로 인한 값 손실 방지
4. 사용자 로그인 없이 브라우저의 데모 세션에 임시 저장
5. [데모 초기화] 실행 시 입력값, 시뮬레이션 예약 상태, 해당 데모 세션의 서버 알림 예약 삭제


FR-4. 확인 요약 (전체 보기 + 필드별 수정)

설명
- 5개 필드가 모두 채워지면 검색 실행 전 선택 사항 전체를 한 화면에 큰 글씨로 표시한다.

표시 예시
- "대전 → 부산"
- "7월 15일 수요일"
- "낮 12시까지 도착"
- "노약자(만 65세 이상) 1명 · 성인 1명 · 학생 0명"
- "총 2명"

동작
- 각 행을 누르면 해당 입력 화면만 열림
- 수정 완료 후 요약 화면으로 복귀
- 다른 필드의 값은 유지
- 하단 [이대로 찾기] 버튼을 누르면 통합 검색(FR-5) 실행


FR-5. 전 수단 통합 검색

설명
- 확정된 입력값(FR-4)으로 KTX·코레일 일반열차·SRT·고속버스·시외버스의 운행정보와 요금을 통합 조회한다.
- 운행정보·요금은 실제 외부 API 응답을 사용한다.
- 유형별 인원수와 사업자별 할인 규칙을 적용해 총요금을 계산한다.
- 학생 할인 규칙을 확인할 수 없는 교통편은 성인 운임을 적용하고 "학생 할인 미적용"을 표시한다.
- 도착 희망 시각 이내에 도착하는 편을 우선한다.

출력
- 후보 경로 목록
  · 교통수단
  · 출발·도착 장소
  · 출발·도착 시각
  · 소요시간
  · 총요금 및 승객 유형별 요금
  · 환승 횟수
  · 데이터 출처 및 확인 시각

데이터 표시
- 실제 API 응답: "운행정보 실제 API 조회 · 오후 2시 10분 확인"
- 목업 데이터를 사용한 항목에만 "시뮬레이션" 표시
- 한 경로 안에서도 운행정보·좌석·예약의 출처를 각각 표시

예외
- 개별 API 장애 시 성공한 교통수단의 결과는 유지
- "일부 교통편은 확인하지 못했어요" 안내
- [다시 확인]을 누르면 실패한 공급자만 재조회
- [확인된 결과만 보기]를 누르면 성공한 결과로 계속 진행


FR-6. 좌석 상태 확인·매진 제외

설명
- 열차 좌석 상태는 korail2·SRTrain의 실제 조회 결과를 사용한다.
- 고속버스·시외버스 좌석 상태는 시뮬레이션 데이터를 사용한다.
- 실제 예약·좌석 선점 함수는 호출하지 않는다.

좌석 상태
- LIVE_AVAILABLE: 실시간 좌석 있음
- LIVE_SOLD_OUT: 실시간 매진
- UNKNOWN: 실시간 조회 실패 또는 확인 불가
- SIMULATED_AVAILABLE: 시뮬레이션상 좌석 있음
- SIMULATED_SOLD_OUT: 시뮬레이션상 매진

화면 표시
- 열차 실제 조회: "좌석 실시간 확인"
- 버스 목업: "좌석 시뮬레이션"
- 조회 실패: "좌석 확인 불가"

동작
- LIVE_SOLD_OUT 및 SIMULATED_SOLD_OUT 경로는 추천 후보에서 제외
- UNKNOWN은 매진으로 처리하지 않음
- UNKNOWN 발생 시 "좌석 정보를 확인하지 못했어요. 다시 확인할까요?" 표시
  · [다시 확인]
  · [시뮬레이션으로 보기]
  · [확인된 결과만 보기]
- [시뮬레이션으로 보기]를 선택하면 UNKNOWN을 시뮬레이션 좌석 상태로 대체하고 카드에 전환 사실 표시
- [확인된 결과만 보기]를 선택하거나 재조회 후에도 UNKNOWN이면 추천 카드에서 제외하고 "좌석을 확인하지 못한 교통편" 영역에 별도 표시

내부 출력
- 추천 가능한 후보 목록
- 매진으로 제외된 후보 목록
- 조회 실패 후보 목록
- 각 후보의 좌석 상태와 데이터 모드


FR-7. 여정 재조합 엔진

설명
- 1순위 수단이 매진이면 다른 수단 또는 환승 조합으로 대체 여정을 생성한다.

입력
- 확정 입력값
- 정규화된 운행 후보 목록
- FR-6 좌석 상태
- 제약값
  · 갈아타기 1회 이하
  · 환승 대기 20분 이상
  · 총 소요시간은 직결 최속편의 1.5배 이하

출력
- 조건을 충족하는 대체 경로 최대 3개
- 경로별 추천 근거 키(빠름, 환승 없음, 저렴함 등)
- 제외 사유

규칙
- UNKNOWN을 매진으로 간주하지 않음
- 시뮬레이션 좌석 상태가 포함된 경로에는 시뮬레이션 표시 유지
- 도착 마감 시각을 넘는 경로는 기본 추천에서 제외
- 직결편이 없는 경우의 비교 기준은 상세 알고리즘과 함께 확정
- 상세 탐색·점수화 알고리즘은 담당 모듈 확정 후 본 항목에 추가


FR-8. 경로 제시 화면

설명
- 조건을 충족하는 경로를 원칙적으로 2–3개, 최대 3개의 큰 카드로 제시한다.
- 후보가 1개뿐이면 1개만 표시하고, 후보가 없으면 결과 없음 화면을 표시한다.

카드 구성
- 추천 근거: "갈아타지 않아요", "가장 빨라요", "가장 저렴해요"
- 교통수단 아이콘과 이름
- 출발 시각(가장 크게)
- 도착 시각
- 총 소요시간
- 총요금 및 인원 구성
- 환승 여부·환승 장소·대기시간
- 운행정보·좌석·예약의 데이터 모드

표시 예시
- 열차: "운행정보 실제 API 조회 · 좌석 실시간 · 예약 시뮬레이션"
- 버스: "운행정보 실제 API 조회 · 좌석/예약 시뮬레이션"

경로 설명
- 구조화된 시간·요금·환승 데이터를 LLM에 전달해 한 문장 비교 설명을 생성
- LLM은 시간·요금·좌석 상태를 변경하거나 새로 만들어서는 안 됨
- LLM 호출 실패 시 "가장 빠름", "환승 없음", "가장 저렴함" 정형 문구로 대체


FR-9. 좌석 선택·선점·결제 시뮬레이션

설명
- 선택한 모든 교통수단의 좌석 선택, 좌석 선점, 예약 및 결제를 시뮬레이션한다.
- 실제 사업자 예약 API와 결제 API는 호출하지 않는다.

좌석 선택
- 시뮬레이션 좌석 배치도 또는 자동 배정 사용
- 기본값: 예약 가능한 시뮬레이션 좌석 자동 배정
- 선택 옵션: [상관없음] [창가] [통로]
- 여러 명이면 인접 좌석 우선 배정
- 실제 열차 좌석 번호가 아니라는 점을 화면에 표시

시뮬레이션 상태
- SIM_HOLDING
- SIM_HELD
- MOCK_PAYMENT_OPENED
- DEMO_COMPLETED
- SIM_EXPIRED
- SIM_CANCELLED
- SIM_FAILED

선점 성공 화면
- "좌석 선점 시뮬레이션이 완료됐어요"
- "실제 예약이나 결제는 이루어지지 않았어요"
- "오후 3시 42분까지 · 12분 남음"처럼 절대 시각과 남은 시간을 함께 표시
- 시뮬레이션 엔진이 생성한 데모 기한 사용
- [결제 화면 체험하기] 버튼 제공

결제 화면
- 상단 고정 문구: "대회 시연용 결제 화면입니다. 실제 결제되지 않습니다."
- 카드정보를 입력·저장하지 않음
- 결제 완료 동작은 DEMO_COMPLETED 상태만 생성하며 실제 PAID 상태를 생성하지 않음

예외
- 시뮬레이션 경합 실패: "방금 자리가 나간 상황을 시연하고 있어요"
- [다른 길 찾기]를 누르면 FR-7 재조합 실행
- 시뮬레이션 기한 만료 시 SIM_EXPIRED로 변경


FR-10. 탑승 안내·이메일 알림

설명
- DEMO_COMPLETED 상태의 시뮬레이션 여정을 저장하고 탑승 안내를 제공한다.
- 사용자 로그인과 이메일 입력 기능은 구현하지 않는다.
- 서버에 미리 등록된 데모 이메일 주소로 안내 메일을 전송한다.
- DEMO_COMPLETED가 되면 알림에 필요한 최소 여정과 데모 세션 식별자를 서버의 데모 알림 큐에 저장한다.
- 서버의 데모 알림 데이터는 마지막 알림 전송 후 삭제한다.

알림 시각
- 출발 전날 오후 6시
- 출발 2시간 전
- 여정 생성 시 이미 출발 2시간 이내라면 즉시 1회 전송
- 모든 시각은 대한민국 표준시 기준

이메일 표시
- 제목과 본문에 "경진대회 시연용 알림" 명시
- 실제 승차권이나 실제 예약으로 오인할 수 있는 표현 금지
- 여정·출발 시각·도착 시각·환승 정보를 포함

시연 지원
- 실제 알림 시각을 기다리지 않고 심사 시 이메일 전송을 확인할 수 있도록 [알림 시연] 버튼 제공


FR-11. 시뮬레이션 예약 확인

설명
- 실제 예약을 생성하지 않으며 데모 세션에 저장된 시뮬레이션 상태만 보여준다.
- 사용자 로그인은 사용하지 않는다.

동작
- 첫 화면에 진행 중인 시뮬레이션 예약이 있으면 최상단 카드로 표시
- 표시 문구: "예약 시뮬레이션이 진행 중이에요 — 오후 3시 42분까지 · 12분 남음"
- 카드에 "시뮬레이션" 배지를 상시 표시
- 탭하면 경로, 데모 식별번호, 시뮬레이션 마감 시간 표시
- 제공 버튼
  · [결제 화면 체험하기]
  · [시뮬레이션 취소]
- 실제 사업자 예약번호는 생성·표시하지 않음
- 화면에 표시하는 예약 상태는 브라우저의 데모 세션 안에서 유지
- 이메일 예약 발송에 필요한 최소 여정은 FR-10의 서버 데모 알림 큐에서 별도로 관리
- [데모 초기화] 시 모든 시뮬레이션 예약 상태와 해당 데모 세션의 서버 알림 예약 삭제

5. 시연 데이터·상태 표시 규칙

1. 실제 외부 응답과 시뮬레이션 값을 동일한 상태명으로 저장하지 않는다.
2. 경로 카드에는 운행정보, 좌석, 예약 각각의 데이터 모드를 표시한다.
3. 시뮬레이션 배지는 색상만으로 구분하지 않고 반드시 "시뮬레이션"이라는 글자를 포함한다.
4. UNKNOWN은 매진으로 변환하지 않는다.
5. 실제 좌석 조회 실패 후 [시뮬레이션으로 보기]를 선택한 경우에만 대체하며 카드에 전환 사실을 명확히 고지한다.
6. 실제 예약·결제 함수는 UI에서만 숨기지 않고 백엔드에서도 비활성화한다.
7. 데모 초기화로 입력값, 목업 결제 상태, 시뮬레이션 예약 상태, 서버 알림 예약을 한 번에 삭제할 수 있어야 한다.

6. 추후 확정 사항

- FR-7 여정 재조합 엔진의 상세 탐색·점수화 알고리즘
- 학생의 정확한 연령·자격 확인 방식과 교통사업자별 승객 유형 매핑
- 상용 서비스용 철도·고속버스·시외버스 공식 B2B API 사용 조건
- 상용 서비스의 사용자 계정 연동·실제 예약·결제 완료 확인 방식
- 경로 비교 설명문에 사용할 LLM 모델과 지연·비용 기준
